## Knomo 1.10.0

Knomo 1.10.0 introduces a simpler Daily Notes-based data architecture, with a rebuildable local Catalog and independent Trash recovery copies.

This redesign brings three main benefits:
- Faster: Browsing, search, filtering, statistics, tags, Shuffle Day, and Time Buoy use the local Catalog directly instead of repeatedly reading large amounts of Markdown.
- Better for multi-device sync: Core Memo content remains plain Markdown. Each device builds its own Catalog from synced Daily Notes, reducing extra files and state issues caused by syncing plugin indexes across devices.
- More reliable: Markdown remains the primary source for active Memos. If the local Catalog has a problem, it can be rebuilt; if Knomo cannot safely identify a change, it stops instead of silently overwriting content.

### Highlights

- Recent 3-day time flow groups ordinary Memos from today, yesterday, and the day before by date in the default All Notes view, with clearer time displays and a separator before older history. You can turn it off in settings to restore the original card layout.
- Customize the Composer toolbar by showing or hiding buttons, changing their order, or restoring the default layout.
- The toolbar now includes bold, highlight, link, and numbered-list actions alongside tags, images, Time Buoy, tasks, and lists.
- Daily Notes remain the source of truth for active Memos. The Catalog powers browsing, search, filtering, statistics, tags, Shuffle Day, Time Buoy, and historical queries.
- The Catalog is stored locally on each device and is not synced across devices. Each device builds its own local data from synced Daily Notes.
- Knomo now updates the Catalog incrementally and only processes changed Daily Notes, reducing repeated reads and unnecessary full rescans.
- Existing Memos in supported - HH:mm and - HH:mm:ss formats are recognized automatically without a separate manual import, while preserving their original time precision.
- Monthly Memos continue to be generated automatically from Daily Notes as a rebuildable monthly projection, not as an independent source of data.
- Memos with identical content remain separate entries. If a target has changed or cannot be uniquely identified, Knomo refuses the operation and asks for a refresh instead of risking an incorrect overwrite.

### Automatic Maintenance

- When Daily Notes change, the Catalog updates incrementally and recognizes supported external Markdown edits.
- Monthly Memos are maintained from the latest Daily Notes; incomplete or stale data will not overwrite an existing projection.
- If the local Catalog becomes unavailable or corrupted, it can be rebuilt from Daily Notes.
- When Knomo detects a conflict or cannot safely identify a target, it reports the issue instead of silently overwriting Memo content.

### Delete and Restore
- Before deleting a Memo, Knomo saves and verifies an independent recovery copy before modifying the Daily Note.
- Restoring writes the selected recovery copy back into the corresponding Daily Note.
- Permanently deleting a recovery copy does not modify other content in current Daily Notes.
- The Trash is intended for accidental-deletion recovery. It is not a Vault backup and does not guarantee complete cross-device recovery.

### Upgrading

- Legacy migration supports the Index used by Knomo 1.2.9 and earlier, converting recoverable Trash records and necessary settings. Active Memos are rebuilt from current Daily Notes.
- After conversion and verification succeed, Knomo saves the migration completion record in plugin configuration, then automatically cleans up the legacy `_knomo-system` folder used by that migration. Cleanup failures are reported and can be retried without importing completed data again.
- If cleanup fails, it can be retried without repeating the completed migration.

Knomo 1.10.0 引入更简洁的 Daily Notes 数据架构，使用可重建的本地 Catalog 和独立的回收站恢复副本。

这次改造主要带来三方面改善：
- 更快：浏览、搜索、筛选、统计、标签、往日漫游和时光浮标等功能直接使用本地 Catalog，不需要反复读取大量 Markdown 文件。
- 更适合多设备同步：核心 Memo 内容仍然只是普通 Markdown，各设备根据已同步到本机的 Daily Notes 建立自己的 Catalog，减少插件索引参与跨设备同步带来的额外文件和状态问题。
- 更可靠：Markdown 始终是活动 Memo 的主要来源。本地 Catalog 出现问题时可以重建；遇到无法确认的修改时，Knomo 会停止操作，而不是静默覆盖内容。

### 主要变化

- 新增近三天时间流：在“全部笔记”默认视图中，将今天、昨天和前天的普通 Memo 按日期分组，突出显示时间，并在更早的历史记录前显示分隔提示。可在设置中关闭，恢复原有卡片样式。
- 输入工具栏支持自定义按钮的显示与隐藏、调整顺序，以及恢复默认布局。
- 工具栏在标签、图片、时光浮标、任务和列表之外，新增加粗、高亮、链接和有序列表操作。
- Daily Notes 继续作为活动 Memos 的事实来源；Catalog 负责浏览、搜索、筛选、统计、标签、往日漫游、时光浮标和历史查询。
- Catalog 仅保存在本机，不参与跨设备同步；各设备根据已同步的 Daily Notes 建立自己的本地数据。
- Knomo 会增量扫描 Daily Notes，只处理发生变化的内容，减少重复读取和不必要的全量处理。
- 已有日记中符合 - HH:mm 和 - HH:mm:ss 格式的 Memos 可直接识别，无需单独手动导入，并保留原有时间精度。
- Monthly Memos 继续根据 Daily Notes 自动生成，是可重建的月度投影，不作为独立的数据来源。
- 同文 Memos 保持为独立条目。目标内容已变化或无法唯一确认时，Knomo 会拒绝操作并要求刷新，避免错误覆盖。

### 自动维护

- Daily Notes 发生变化后，Catalog 会自动增量更新，并识别受支持的外部 Markdown 修改。
- Monthly Memos 会根据最新的 Daily Notes 自动维护；不完整或过期的数据不会覆盖已有投影。
- 本地 Catalog 出现问题时，可根据 Daily Notes 重新建立。
- 遇到冲突或无法明确确认的修改时，Knomo 会报告问题，而不是静默覆盖 Memo 正文。

### 删除与恢复
- 删除 Memo 前，Knomo 会先保存并验证独立的恢复副本，再修改 Daily Notes。
- 恢复时，会将选中的恢复副本重新写入对应的 Daily Note。
- 永久删除只会删除恢复副本，不会修改当前 Daily Notes 中的其他内容。
- 回收站用于误删恢复，不等同于 Vault 备份，也不保证跨设备恢复副本始终完整。

### 升级说明

- 旧版迁移支持 Knomo 1.2.9 及以下的 Index，转换仍需恢复的回收站记录和必要设置；活动 Memos 从当前 Daily Notes 重建。
- 转换和验证成功后，Knomo 将迁移完成记录保存到插件配置，再自动清理本次迁移使用的旧 `_knomo-system` 文件夹。清理失败时会报告并可重试，不会重复导入已完成迁移的数据。
- 如果清理失败，可以重新尝试，不会影响已经完成的数据迁移。

### 许可变更

Knomo 1.10.0 从 MIT 改为 **GPL-3.0-only，加 Knomo Obsidian 宿主附加许可**。历史 MIT 授权和第三方许可继续有效。
