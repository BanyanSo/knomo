## Knomo 1.8.0

Knomo 1.8.0 introduces a new data architecture. While continuing to use Daily Notes and plain Markdown as its foundation, it provides a more reliable data layer for Memos, improves automatic discovery, and reduces routine data maintenance.

### Highlights

- Added a local Catalog architecture. Daily Notes remain the source of truth for memo content, while the Catalog provides data for browsing, search, filtering, statistics, tags, Shuffle Day, Time Buoy, and historical queries. It can be rebuilt from Vault data when needed.
- Improved handling of external Markdown edits, incremental scanning, recovery from abnormal states, and multi-device usage. Routine data maintenance is handled automatically whenever it can be completed safely, reducing the need for manual maintenance operations in Settings.
- Existing Memos in Daily Notes using the supported `- HH:mm` and `- HH:mm:ss` formats no longer require a separate manual import. Monthly Memos are generated automatically from Daily Notes.
- Automatically migrates the base metadata used by older versions of Knomo during upgrade.

### Automatic Maintenance

- By default, Knomo handles routine data tasks including:

```
- Scanning Daily Notes and discovering supported Memos;
- Building and updating the local Catalog;
- Creating identity metadata for historical Memos;
- Handling supported external Markdown changes;
- Maintaining Monthly Memos;
- Resuming routine interrupted tasks.
```

- The new version reduces manual import, rebuild, repair, and other data-maintenance actions in Settings. When conflicts, ambiguities, or abnormal states cannot be handled safely and automatically, Knomo uses conservative behavior instead of silently overwriting data.

### Upgrading

- Knomo automatically migrates the base metadata used by older versions and rebuilds the new local metadata store in the `_knomo-data` folder.
- After migration, legacy Knomo data is retained. Once you have confirmed that all devices have been upgraded to the new version of Knomo and are working normally, you may manually delete the legacy `_knomo-system` folder.
- Backing up your Vault before upgrading is recommended.

Knomo 1.8.0 引入新的数据架构，在继续以 Daily Notes 和普通 Markdown 为核心的基础上，为 Memos 建立更可靠的数据基础、自动发现能力，并减少日常数据维护。

### 主要变化

- 新增本地 Catalog 数据架构：在保持 Daily Notes 为正文真相来源的前提下，为浏览、搜索、筛选、统计、标签、往日漫游、时光浮标和历史查询提供数据，并可以根据 Vault 数据重新建立。
- 改进外部 Markdown 修改、增量扫描、异常恢复和多设备使用；在可以安全完成时自动处理日常数据维护，减少设置中的手动维护操作。
- 已有日记文件里的 Memos 在受支持 `- HH:mm` 和 `- HH:mm:ss` 内容格式下，无需再执行单独的手动导入，Monthly Memos 根据 Daily Notes 自动生成。
- 升级时自动迁移使用旧版本 Knomo 的基础元数据。

### 自动维护

- Knomo 会默认处理常规的数据工作，包括：
```md
- 扫描 Daily Notes 并发现受支持的 Memos；
- 建立和更新本地 Catalog；
- 为历史 Memos 建立身份元数据；
- 处理受支持的外部 Markdown 修改；
- 维护 Monthly Memos；
- 继续常规的中断任务。
```
- 新版 Knomo 的设置中减少了手动导入、重建、修复以及其他数据维护操作。当冲突、歧义或异常状态无法被安全自动处理时，Knomo 会采用保守处理，而不是静默覆盖数据。

### 升级说明

- Knomo 会自动迁移使用旧版本 Knomo 基础元数据，并重新建立新的本地元数据存储在文件夹`_knomo-data`。
- 迁移完成后会保留 Knomo 旧版数据，确认所有设备都已升级到新版 Knomo 并运行正常后，可自行删除旧版数据文件夹`_knomo-system`。
- 升级前建议备份 Vault。
